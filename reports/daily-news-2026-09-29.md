A cluster of seven ESP32-S3 boards can run a quantized language model by dividing inference across separate microcontrollers. The [ESP32s3-LLM-Cluster project on GitHub](https://github.com/Low-Zi-Hong/ESP32s3-LLM-Cluster) assigns one board to orchestration and six boards to transformer computation. The repository title describes a 0.4B model, while its architecture notes describe a sliced 0.5B model. That mismatch leaves the exact model size unclear, but the system design remains specific: the boards use 1.58-bit ternary weights, custom ESP-IDF firmware and high-speed SPI links to pass the model state from one board to the next. ## One prompt, seven boards The master board accepts a prompt, runs the BPE tokenizer and looks up token embeddings. The embedding data uses INT4 storage and occupies about 14 MB of flash. The master then sends each hidden-state vector to the first compute board through one SPI channel. Each compute board handles four transformer blocks. The first node processes layers 0 through 3. The next nodes continue the sequence until the sixth compute board finishes layers 20 through 23. Every node runs RMSNorm, attention, rotary positional embeddings, a key-value cache and the model's multilayer perceptron layers. The final compute node sends its result back to the master through the return side of the SPI chain. The master applies the final RMSNorm, runs the language-model head and selects the next token with greedy sampling. The project stores the final normalization data in a 64 KB `fnorm` partition and ties the language-model head to the INT4 embedding table. The topology turns seven small boards into one inference pipeline. Each board keeps a limited portion of the model in memory, while the SPI chain carries the intermediate state between stages. ## Ternary weights reduce storage pressure The compute nodes use a 1.58-bit representation with three weight values, commonly mapped to -1, 0 and 1. The format cuts storage demand and simplifies parts of the matrix multiplication path. The firmware includes a custom `bitlinear` implementation and an assembly file for multiply-accumulate operations. The project combines that weight format with FP16 and FP32 arithmetic. RMSNorm scales FP16 values into FP32 calculations, while the pipeline sends FP32 hidden-state vectors between nodes. The design trades compact model storage for conversion work and data movement. The attention runtime includes RoPE and a KV cache stored in PSRAM. The cache lets the system retain key and value states across generated tokens, which reduces repeated work during autoregressive generation. The SPI links still carry each stage's output, so chain length and transfer size will shape response time. ## Firmware and preparation tools The repository separates master firmware, node firmware and PC-side preparation scripts. The master code handles user input, tokenization, embedding lookup, SPI control and sampling. The node code handles the inference loop, ternary linear layers, attention and DMA-based SPI transfers. The Python tools prepare model files before flashing. They include scripts for vocabulary pruning, embedding slicing, quantization-aware training, INT4 packing, tokenizer serialization and model chunk packing. The custom partition tables reserve flash regions for tokens, embeddings, model layers and normalization data.
