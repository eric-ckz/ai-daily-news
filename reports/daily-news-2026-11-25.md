We ask the reverse question: given an implemented artifact, such as a layout, a gate-level netlist or a protected simulation model, can an agent work out what it does well enough to act on that knowledge? We introduce HWRE-Bench, a benchmark for agentic hardware reverse engineering built on one observation. Each step of the forward flow discards information (names, hierarchy, word-level structure, generator parameters, the programming model), and a reverse-engineering task asks the agent to recover what was lost and to prove it with an executable deliverable that the artifact alone cannot supply. Since layout extraction is now mechanical and a correct netlist is already a cycle-exact model, every task carries a mandatory *copy-the-netlist* control that must score zero. HWRE-Bench spans five tracks (Extract, Abstract, Audit, Interoperate, Modify), four information-loss levels and white- versus black-box access, all on original designs. 6. **How AI Agents Are Transforming Software Development Workflows - Interview Node Blog**
   - 摘要：### **Section 1: How AI Agents Are Changing the Traditional Software Development Lifecycle** ##### **From Code Completion to Autonomous Development Tasks** Traditional AI coding assistants primarily supported developers at the point of code creation. They could suggest the next lines of code, generate functions, explain syntax, or provide answers about programming concepts. The developer remained responsible for deciding what to inspect, which files to modify, which commands to execute, and how to verify the result. Coding agents introduce a task-oriented interaction model. A developer can describe an objective such as fixing a failing API endpoint, adding pagination to a service, or improving test coverage. The agent can then inspect the repository, identify relevant components, formulate a plan, and perform a sequence of operations. The difference is architectural as much as functional. A code completion system generally receives a limited context and returns a suggestion. An agent operates through an execution loop involving model reasoning, tool selection, observation, and subsequent action. It can inspect command output, respond to test failures, and revise its implementation based on new information. For example, suppose a developer asks an agent to add pagination to a customer API. The agent may first inspect the routing structure, identify the controller and database query, review existing response formats, and locate related tests. It can then modify the implementation, add pagination parameters, update tests, and run the relevant test suite. This workflow requires the agent to understand more than the syntax of the programming language. It must recognize repository conventions, dependencies, API contracts, error-handling patterns, and architectural boundaries. The developer's responsibility changes accordingly. Instead of manually controlling every small implementation step, the engineer increasingly defines the objective, establishes constraints, provides relevant context, and evaluates the resulting changes. This does not mean that all development tasks should be delegated. Small edits, ambiguous requirements, sensitive architectural changes, and high-risk production modifications may still benefit from direct human implementation. The appropriate level of autonomy depends on task complexity, reversibility, and the quality of available validation. The important shift is from AI as a code suggestion mechanism to AI as a participant in a controlled engineering workflow. ##### **AI Agents in Requirement Analysis and Technical Planning** Software development begins before code is written. Engineers need to understand user requirements, identify technical constraints, clarify expected behavior, and determine how a proposed change fits into the existing architecture. AI agents can assist with this discovery process by analyzing requirement documents, issue descriptions, product specifications, API documentation, and existing source code. They can identify potentially affected components, summarize dependencies, and generate an initial implementation plan. Consider a requirement to introduce role-based access control into an existing application. An agent could inspect the authentication middleware, user model, route definitions, and authorization checks. It could identify endpoints that may need changes and prepare a dependency map for the engineering team. An agent could also convert an unstructured product requirement into technical tasks. For example, a request to allow users to export reports might be divided into API development, background processing, file generation, storage, authorization, and interface updates.
