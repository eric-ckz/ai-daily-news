6. **New MIT and Sakana AI framework uses an LLM judge to cut evaluation costs for self-improving coding agents | VentureBeat**
   - 摘要：Coding agents can improve by changing the prompts, tools and code that guide their work. But finding which changes actually help and are worth preserving is challenging and expensive. Each candidate change needs testing, and a search across many candidates can consume thousands of CPU hours and cost thousands of dollars. Recursive Self-Improvement via Fast Tree Search (SIFT), a framework from researchers at MIT and Sakana AI, tries to cut that evaluation cost. It uses a separate language model to compare candidate agents before committing to expensive benchmark runs. It can also propose new changes while earlier candidates are still being evaluated. That lets the search explore several branches without waiting for a full test after every patch. On the Polyglot coding benchmark, one SIFT run reached 35.1% accuracy in under five hours of wall-clock time, using 42 CPU hours and about $150 in API credits, according to the researchers. For teams tuning coding-agent harnesses against well-defined tasks, SIFT suggests a way to spend expensive evaluations more selectively rather than running every candidate through the full test suite. ## Every improvement needs a test Engineers can tune a coding agent’s instructions, add tools or change how it responds to failures. But hand-tuning takes expert time and limits the search to ideas people think to try. Recursive self-improvement automates part of that process by allowing the system to modify its own source code. In the self-improvement loop, an agent examines failures and proposes a patch to its harness. The revised agent attempts the target tasks, and its score helps determine which version becomes the starting point for another patch. Because a patch changes the system that will propose or execute later work, improvements can build on one another. Earlier approaches manage this search in different ways. Darwin Gödel Machine (DGM) maintains an archive of agents and checks candidates on increasingly large task sets: first 10 tasks, then 50, with the full Polyglot benchmark held back for final evaluation. The Huxley-Gödel Machine (HGM) considers how an agent and its descendants perform when choosing where to search next. It varies the number of randomly sampled tasks used to evaluate candidates. The main challenge is the cost of testing modifications to the agent harness. In the paper’s cost breakdown, proposing a patch costs about 12 cents. A pairwise judge call costs about 4.4 cents, and SIFT uses up to 10 per candidate, or up to roughly 44 cents. Evaluating an agent on 50 Polyglot tasks costs about $6 and 2.6 CPU hours. 8. **AWS Releases Decision Model for AI Agents That Routes Without Generating Any Text**
   - 摘要：AWS Strands Labs released an open-source model on Thursday that removes text generation from the agent decision loop entirely. Instead of predicting tokens, Strands Decider 2B reads a situation, compares its hidden-state representation against each candidate answer, and returns a ranked probability list in a median 115 milliseconds on a consumer GPU, according to benchmarks in the package release. The release arrived on the same day Cloudflare shipped its own decision-model pair, Clef and Clef-flash, as described in the Cloudflare announcement post, suggesting the category TypeSafe AI named "System One models" at its September 15 launch is hardening into a recognizable infrastructure tier rather than remaining a single vendor's idea. The model is published at ``` StrandsAgents/strands-decider-2B-hobson-v19 ``` on Hugging Face under an Apache 2.0 license, meaning commercial use, modification, and redistribution require no licensing fees. It is installable in one command ( ``` pip install strands-decider ``` ) and comes with a command-line interface and an HTTP server, as confirmed by the package's PyPI listing. No managed hosted inference endpoint exists yet; the bundled server binds to localhost with no authentication layer, which means teams deploying to shared infrastructure need to add access controls themselves. ### What Problem Decision Models Solve in Agent Pipelines An AI agent running in production spends much of its time on decisions that do not require language generation at all: which tool should I call next, is this argument grounded in what the user actually said, does this output meet the requested quality bar, which queue should own this request. Routing each of those through a frontier large language model is slow and expensive by construction — frontier APIs generate text one token at a time whether the task needs a paragraph or a one-word answer. The decision-model category, now represented by Strands Decider 2B, Cloudflare's Clef and Clef-flash, and TypeSafe AI's closed-API Jev, proposes a structural answer detailed in the TypeSafe launch blog: some choices inside an agent loop do not need a language model at all. They need a model that picks reliably from a bounded option set, reports how confident it is, and does so quickly enough to sit on the hot path without becoming the new bottleneck. The TypeSafe team borrowed the term "System One" from cognitive psychologist Daniel Kahneman's framework distinguishing fast, automatic judgment (System 1) from slow, deliberate reasoning (System 2) — though it is worth noting that even Kahneman's collaborator Keith Stanovich has since moved away from the System 1/2 framing as overly simplified. The AI analogy is looser than the marketing suggests, but the engineering problem it describes is real. ### How the Pointer Head Architecture Works The core mechanism of Strands Decider 2B is a departure from standard language-model design. The team took Qwen3.5-2B-Base, a 1.9-billion-parameter decoder model produced by Alibaba's Qwen team and published as open weights, and made a targeted structural change: they removed the language-modeling head — the component responsible for predicting the next word — and replaced it with a pointer head of roughly one million parameters, as described in the project's architecture documentation.
