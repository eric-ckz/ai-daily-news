This pipeline aims to address documentation drift in fast-paced engineering environments. * [TechGig](/agency/87450652/TechGig "TechGig") * Published On Nov 10, 2026 at 06:45 AM IST ## Highlights * Trent AI built a multi-agent code-to-doc pipeline on OpenClaw for automated documentation. * The system uses Change Scanner, Doc Classifier, Doc Publisher, and Orchestrator agents. * Deployment on AWS prioritised security with no public IP and restricted egress. * GitHub App permissions and branch protection limit agent actions and require human review. Trent AI has built a multi-agent system on [OpenClaw](/tag/openclaw) to automate the generation of public documentation from code, the company said. This initiative aims to address documentation drift, where engineering teams ship features rapidly while documentation falls out of date. The system uses OpenClaw's agentic capabilities and is composed of several agents. These include a Change Scanner, a Doc Classifier, a Doc Publisher, and an Orchestrator, along with [GitHub](/tag/github) Tools. ### Multi-agent system architecture The Change Scanner reads code repositories, fetches merged pull requests, and identifies impacted files. The Doc Classifier triages changes into categories like breaking changes or new features, assigning a confidence score. The Doc Publisher converts raw files into customer-facing documents, reconciles existing documentation, and creates a pull request with updated content. An Orchestrator coordinates these components, tracks failures, and runs the pipeline on a schedule. GitHub Tools are scripts connecting to GitHub, used by the Change Scanner and Doc Publisher. Trent AI developed an agent for each component to understand [multi-agent systems](/tag/multi-agent+systems). OpenClaw currently lacks clear context handoff for multi-agent work, so Trent AI used shared files for context exchange. This is a common practice for long-running agents. ### Secure AWS deployment Trent AI deployed the agents safely on AWS, guided by principles of least privilege and a tight blast radius. The system only receives necessary access, and any compromise remains contained within the documentation pipeline. A security review, using Trent's Claude Code Security, identified threats such as data exfiltration, code pollution, and secret leakage. Mitigations were mapped to risks for each agent and network path. The AWS deployment uses a single EC2 instance within a VPC, without a public IP or inbound rules. Access is limited to AWS Systems Manager Session Manager, removing the need for SSH keys. Egress traffic is controlled by AWS Network Firewall with a stateful FQDN allow-list. This restricts the instance to communicating only with essential services like GitHub and the Bedrock control plane. Agents authenticate via a dedicated GitHub App installed only on the relevant repository, with permissions scoped to pull\_requests:read+write and contents:read+write. No admin access or metadata writes are permitted. GitHub's branch protection requires human review for every pull request opened by the agents. The agents can propose changes but cannot merge their own work. OpenClaw's agentToAgent setting, a boolean with an allow-list of agent IDs, gates inter-agent calls.
